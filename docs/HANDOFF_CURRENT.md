## 0. Регламент ведения этого документа

Чтобы контекст не протухал, как это случилось с `README.md`:

1. **В начале сессии** агент читает этот файл целиком. Этого должно хватать для входа в работу без чтения кода.
2. **В конце сессии** агент обновляет разделы 5 (открытые долги), 6 (сетапы) и 7 (журнал сессий).
3. **Дату и время в шапке** обновлять обязательно. Устаревшая шапка обесценивает документ.
4. **Разделы 1–4 меняются редко** — только при смене архитектуры или методологии.
5. **Крупные инженерные разборы** уезжают в `AGENT_HANDOFF_<дата>.md`, здесь остаётся ссылка и одна строка сути.
6. **Правило про факты:** сюда попадает только то, что проверено. Гипотезы помечаются явно словом «гипотеза».

## 1. Архитектура: строгое разделение ролей

```
┌────────────────────────────────────────────────────────┐
│ 1. АЛГОРИТМЫ В КОДЕ (Python Core — 24/7):              │
│    • Реалтайм-потоки Tinkoff Stream и MOEX ISS         │
│    • VWAP, ATR, RSI, ADX, сжатие, оборот ₽             │
│    • Базовая сетка уровней (trade_plan)                │
│    • Субминутное зарождение движения (EARLY_MOVE)      │
└───────────────────────────┬────────────────────────────┘
                            ▼
┌────────────────────────────────────────────────────────┐
│ 2. AI-АГЕНТ (аналитик в чате):                         │
│    • Фильтрует математику по стакану, ленте и VWAP     │
│    • Отсеивает ловушки (ПОЗДНО / шорт против спроса)   │
│    • Выдаёт финальный сигнал и заносит в журнал        │
└───────────────────────────┬────────────────────────────┘
                            ▼
┌────────────────────────────────────────────────────────┐
│ 3. РИСК-ДВИЖОК (src/risk/engine.py):                   │
│    • Размер позиции и лимиты депозита                  │
│    • Ограничение убытка стоп-лоссом                    │
└────────────────────────────────────────────────────────┘
```

**Почему код не надо усложнять.** Чистые формулы в `technical.py`, `intraday.py`, `stream.py` — надёжный поставщик цифр. Интеллектуальная фильтрация, оценка контекста и выбор сделок — работа агента, а не кода.

**Железное правило фиксации.** Каждый выданный человеку сигнал уходит через `POST /api/analyst-signal` в таблицу `predictions`, оценивается по факту закрытия (`intraday_outcome`) и формирует объективную статистику. Сигнал, не записанный в журнал, не существует.

## 2. Методология: 5 шагов проверки сделки

Смотреть на «голый» график запрещено. Обязателен прогон по боевым эндпоинтам:

```
ШАГ 1: «ГДЕ ДЕНЬГИ?»        /api/universe → /api/screen → /api/volume-scan
ШАГ 2: «МАТЕМАТИКА»         /api/analyst-brief/{ticker}
ШАГ 3: «УМНЫЕ ДЕНЬГИ»       /api/live/{ticker} → /api/orderbook-index
ШАГ 4: «ЗАСЛОН ОТ ЛОВУШЕК»  /api/analyst-memory → /api/geopolitics
ШАГ 5: «ВЫДАЧА И ЖУРНАЛ»    POST /api/analyst-signal
```

### 2.1. Правило 3 подтверждений для шорта в RANGE

Закреплено в `ANALYST_RULES` (`src/agent/analyst_memory.py`):

> В боковике (RANGE) шорт у верхней границы требует 3 подтверждения: слом под VWAP, давление в стакане и отсутствие институционального покупателя.

**Отрыв от SMA20 — это топливо, а не баг.** Под VWAP скапливаются стопы покупателей, и их каскад двигает цену.

**Как отличить прибыльный шорт от ловушки:**

| | `SIBN` — профит 10/10 | `SNGS` — ловушка 2/10 |
| :--- | :--- | :--- |
| VWAP | пробит вниз (489,20 ₽) | цена отказалась падать под VWAP |
| Стакан | агрессивные продажи, `orderbook_index = 32` | институциональный приток |
| Контекст | каскад чужих стопов | +2,76% за день, оборот 1,9 млрд ₽ |
| Вывод | шорт отработал | шорт против крупного покупателя — ошибка |

### 2.2. Метка «⚠️ ПОЗДНО»

Сетап помечается `late`, если цена ушла далеко от зоны входа и `R/R` упал ниже 1.5.
Пример 07.08, 16:00 МСК: `SBER` 281,00 ₽ и `VTBR` 55,20 ₽ — агент отказался шортить вдогонку. Далее `SBER` отскочил до 282,64 ₽, `VTBR` до 55,91 ₽. Предупреждение уберегло от входа на дне.

## 5. Открытые долги

По состоянию на 16.08.2026.

### Высокий приоритет

1. **`README.md` описывает не тот проект.** В нём MVP «Telegram + RuBERT → индекс настроения 0–100», тогда как система давно стала интрадей-платформой с Tinkoff-стримом, детекторами событий и LLM-агентом. Любой новый читатель понимает проект неверно.
2. **`src/db.py` (181 КБ) и `src/api/main.py` (175 КБ) блокируют работу.** В коммите `86809e4` правка читателя уже была отложена именно из-за размера файла. Нужен распил на модули.
3. **CI ненадёжен.** GitHub Actions трижды подряд не выделял раннеры («The job was not acquired by Runner of type hosted»), готовый патч лежал неприменённым. Нужен гарантированный локальный прогон как обязательный шаг.

### Средний приоритет

4. **Тесты местами прогоняются вручную** прямым вызовом функций `test_*`, потому что в песочнице нет pytest. При 72 файлах это риск пропустить регресс.
5. **SQLite как основное хранилище** — узкое место для потока стакана и ленты. В планах PostgreSQL / ClickHouse.
6. **Патч `scripts/_patch_series.py`** ждёт применения: `candle_series` собирает выходной словарь вручную, и новые колонки в него не попадают у остальных потребителей (API, сканеры).

## 8. Уроки, оплаченные поломками

Выжимка из разборов в истории коммитов. Читать перед тем, как что-то пушить.

1. **Зелёные тесты не доказывают, что проверенный код уехал в репозиторий.** Проверять надо список файлов в пуше, а не только итог прогона. Патч без функции, на которую он ссылается, ломает сборку целиком (`0c26c48`).
2. **Наличие колонки в таблице не значит, что читатель её отдаёт.** Читатель может собирать словарь руками из фиксированного набора полей (`86809e4`).
3. **Ноль наружу не едет.** `lot = 0` значит «не знаем», `turnover_rub = 0` значит «не посчитано». Отдать такой ноль опаснее, чем не отдать ничего: потребитель умножит и получит тихий ноль вместо честного пропуска.
4. **Молчаливый ноль строк — это баг, а не пустые данные.** Перепутанный аргумент `source` в `micro_series` давал пустой блок при 81850 записях в таблице.
5. **Значения по умолчанию врут убедительнее ошибок.** `limit=400` в `level_series` выглядел как смерть сборщика, а был дефолтом.
6. **Считать надо то, что имеешь в виду.** Уровни — поток событий: 61615 строк на 1020 минут. Метрика «минут» должна считать уникальные `ts`, иначе полнота ряда врёт в десятки раз.
7. **Healthcheck может падать из-за отсутствия бинарника, а не из-за мёртвого сервиса.** Для оркестратора разницы нет: деплой неудачен, в проде остаётся старый образ.
