# MOODEX — Журнал стратегий

Живой документ. Здесь описываем **каждую стратегию** агента: как она задумана,
как реализована в коде **сейчас**, где пробелы и что улучшать. Обновляем файл
при любом изменении логики, чтобы не терять контекст между сессиями.

Легенда статуса:
- ✅ реализовано;
- ⚠️ реализовано частично / с нюансом;
- ❌ пока не реализовано.

---

## Общий конвейер сигнала

```
Данные → NLP/агрегация → Claude (синтез) → сигнал → журнал в БД → оценка по факту → обучение
```

Ключевые модули:
- Сбор: `src/collector/*` (Telegram, Пульс, RSS, MOEX-цены, Tinkoff, сделки трейдеров).
- NLP и агрегация: `src/nlp/sentiment_analyzer.py` (RuBERT), `src/aggregator/aggregator.py`.
- Аналитика: `src/analysis/*` (технический анализ, макро, фундаментал, геополитика).
- Агент: `src/agent/analyst.py` (оркестратор), `src/agent/claude_agent.py` (LLM),
  `src/agent/predictor.py` (обучаемая fallback-модель), `src/agent/scanner.py` (фоновый скан),
  `src/agent/context_builder.py` (память и контекст для Claude).
- Хранилище/журнал: `src/db.py` (модели `Prediction`, `TrackedTrader`, `Channel`, `Setting`, `SentimentDaily`).
- API/UI: `src/api/main.py`, `dashboard/index.html`.

## Стратегия 1 — «Синтез фона + настроения + техники с самообучением»

### Идея (как задумано)
Парсер собирает данные по сделкам трейдеров за день (общий фон «умных денег»),
собирает настроение толпы (что пишут в Пульсе и чатах), собирает графики и
технический анализ. Claude всё это анализирует и выдаёт сигнал. Сигналы
сохраняются в память, ведётся журнал: какие оказались верными, какие нет; агент
анализирует их, **находит причину**, почему сработали/не сработали, и улучшает
стратегию на этих данных.

### Как реализовано сейчас (по коду)

| # | Шаг задумки | Статус | Где в коде |
|---|-------------|--------|-----------|
| 1 | Сделки трейдеров («умные деньги») как фон | ⚠️ | `collector/pulse_author_collector.py`, `GET /api/smart-money`, список трейдеров в БД (`db.TrackedTrader`) + `.env` `PULSE_TRACKED_AUTHORS` |
| 2 | Настроение толпы (Пульс + Telegram-чаты) | ✅ | `collector/telegram_collector.py`, `collector/pulse_collector.py`, `collector/rss_collector.py`, `nlp/sentiment_analyzer.py` (RuBERT), `aggregator/aggregator.py` |
| 3 | Графики + технический анализ | ✅ | `analysis/technical.py` (SMA/RSI/MACD/ADX, `trade_plan`), `collector/moex_price_collector.py`, `collector/tinkoff_client.py` (стакан/поток/объём), `agent/chart_generator.py` + Claude Vision (`analyze_chart`) |
| 4 | Claude синтезирует и выдаёт сигнал | ✅ | `agent/analyst.py::analyze` → `agent/claude_agent.py::synthesize_ticker` (+`analyze_chart`); итог: `direction`/`confidence` (голосование текст 60% / график 40%); при недоступности Claude — fallback `predictor.fuse` |

Плюс прежние `analyst.retrain` (веса fallback) и `build_memory_context` |

### Важные честные нюансы по шагу 7 (самообучение)
Сейчас «обучение» — это **две отдельные вещи**, и обе слабее, чем «агент находит
причину и улучшает стратегию»:

1. **Переобучение весов (`retrain` → `predictor.train_weights`).**
   Обучается лёгкая логистическая регрессия на признаках `[sentiment_signal,
   technical_score]` по оценённым прогнозам. **НО** эти веса используются только
   **fallback-моделью** (когда Claude недоступен). Когда Claude доступен, финальное
   решение принимает он, и переобученные веса на его сигнал **не влияют**.

2. **Память в контексте (`build_memory_context`).**
   Перед решением Claude получает свои прошлые прогнозы по тикеру, общую точность
   и предупреждение, если точность < 45%. Это «обучение в контексте», но это
   **не** структурный разбор: система не анализирует, *почему именно* сигнал не
   сработал (новость? ложное настроение толпы? поздний вход? смена режима рынка?)
   и не превращает эти выводы в правила стратегии.

**Вывод: шаги 1–6 работают как задумано (с оговорками ниже). Шаг 7 теперь
замкнут на базовом уровне — см. блок «Разбор ошибок» ниже.**

### Разбор ошибок (post-mortem) — реализовано
Цикл «находит причину и учится на ней» теперь работает так:

1. **Снимок контекста при прогнозе.** В момент сигнала `analyst.analyze` сохраняет
   в БД (`Prediction.context_json`) ключевые драйверы: настроение, режим, RSI,
   теханализ, «умные деньги», сигнал графика, ключевой инсайт и риск.
2. **Оценка по факту.** По истечении горизонта `evaluate_due_predictions` сверяет
   с ценой MOEX и помечает верно/неверно + доходность (как и раньше).
3. **Разбор причины.** `generate_post_mortems` по каждому закрытому, но ещё не
   разобранному сигналу зовёт `claude_agent.post_mortem`: Claude по снимку
   контекста и факту формулирует **причину** успеха/провала, **урок** и
   **теги** причин (`false_sentiment`, `crowd_trap`, `news_shock`,
   `regime_change`, `late_entry`, `tech_break_fail`, `low_liquidity`,
   `overconfidence`, `correct_read`, `luck`). Если Claude недоступен —
   эвристический разбор по числам (без LLM).
4. **Обратная связь в стратегию.** `build_lessons_context` собирает частые
   причины провалов + свежие уроки и **подмешивает их в промпт** следующих
   прогнозов (блок «🎓 УРОКИ ИЗ ПРОШЛЫХ ОШИБОК»), чтобы агент не наступал на
   те же грабли.

Запуск: автоматически внутри `evaluate_due_predictions` (live-цикл и кнопка
«обучение»), либо разово через `POST /api/agent/post-mortem`. Просмотр —
`GET /api/lessons` (уроки + частота тегов причин).

Что пока **не** входит в разбор: post-mortem влияет на решения только «мягко»,
через контекст промпта; он ещё не меняет численные веса факторов (вес графика,
smart-money vs настроение) — это следующий шаг.

### Голосование «текст 60% / график 40%» — почему так
В `analyst.analyze` финальное направление = взвешенное голосование текстового
вывода Claude и визуального разбора графика:
`score = text_w·(sign·conf)_текст + chart_w·(sign·conf)_график`.
По умолчанию **текст 0.6 / график 0.4**, потому что текстовый вывод опирается на
МНОГО входов (макро, фундаментал, техника в числах, настроение, стакан, «умные
деньги», память, уроки), а разбор графика — это **один** визуальный сигнал.
Это **эвристика, не подобранная по бэктесту**. Вес вынесен в переменную
окружения `CHART_VOTE_WEIGHT` (0..1, по умолчанию 0.4), чтобы его можно было
настраивать, а в перспективе — сделать обучаемым по трек-рекорду.

### Сохранение данных (это наш ресурс)
Что **сохраняется в БД** и переживает перезапуск/редеплой:
- ✅ Сигналы/прогнозы + результат + разбор ошибок и уроки (`Prediction`).
- ✅ Отслеживаемые трейдеры (`TrackedTrader`), Telegram-каналы (`Channel`),
  веса модели (`Setting`), дневные снимки настроения (`SentimentDaily`).

контейнера, вне тома) — при пересборке образа журнал терялся. Исправлено:
теперь БД лежит в `./data/moodex.db`, а `./data` смонтирован на постоянный том
`moodex_data` (см. `docker-compose.yml`). Для масштаба можно переключить

- Сделки Пульса видны **с задержкой**, без размера позиции и плеча; из некоторых

- Переобучение весов ≠ дообучение Claude.
- Не является инвестиционной рекомендацией.

## Архитектура принятия решений: 3 слоя + авто-триаж

Так это работает (и почему автоматически, а не по кнопке):

1. **Словари (сбор + дешёвая тональность).** Пульс/Telegram/RSS → `keyword_sentiment`
   → агрегатор строит индексы настроения по тикерам. Работает постоянно.
2. **Индикаторы / ML (черновой сигнал).** `analysis/technical.py` (тренд, RSI, MACD,
   ADX, `trade_plan`), `agent/predictor.py` (обучаемая логрег-модель) и интрадей-
   детекторы (`analysis/intraday.py`: VWAP, ORB, сжатие→расширение, вынос).
3. **Claude (точный вердикт).** Подтверждает интересные сигналы и формирует
   финальное решение с обоснованием (`agent/claude_agent.py`).

**Авто-триаж (ключевое для дневной торговли — скорость).** Раньше анализ
запускался только по кнопке «Анализировать» (нет клика → нет анализа) ИЛИ фоновый
сканер гонял Claude по всем тикерам подряд (дорого/медленно). Теперь:
`agent/screen.py::interest_score` постоянно (в фоне, live-движок) считает
«интересность» каждого тикера **дёшево, без Claude** (словари + индикаторы +
интрадей). Тикеры выше порога `SCAN_MIN_INTEREST` (не более `SCAN_MAX_CLAUDE` за
цикл) автоматически уходят на подтверждение Claude
(`scanner.scan_interesting`), который и создаёт итоговый сигнал в журнал.

Итог: **словари собрали → ML нашёл интересное → Claude подтвердил и выдал сигнал**,
и всё это само, как только появляется что-то стоящее, без ручного клика.

Настройки: `SCAN_MIN_INTEREST` (порог, дефолт 0.5), `SCAN_MAX_CLAUDE` (лимит
вызовов Claude за цикл, дефолт 6). Включение фонового движка — кнопки «Live-сигналы»
или `POST /api/live-signals/start`. Посмотреть текущий триаж без Claude —
`GET /api/screen`.

**Согласованность карточки.** Интрадей-сетап сверяется со старшим (дневным)
трендом: контртренд к сильному тренду (ADX≥25) или слабый R/R (<1) → «наблюдение»,
а не ложный вход. Когда интрадей ведёт вход — карточка показывает интрадей-план
и согласованные метрики (не дневной шорт под лонг-заголовком).

**Интрадей-график.** На карточке AI-агента есть кнопка «Интрадей 5м» — график
переключается на 5-мин свечи (реалтайм Tinkoff или MOEX с задержкой, помечается),
чтобы картинка совпадала с интрадей-сигналом. Эндпоинт
`GET /api/technical/{ticker}/intraday`.

## Формат торговли: ИНТРАДЕЙ (день-трейдинг)

Уточнение по проекту: торгуем **внутри дня**, а не по дневным свечам.
Параметры (согласовано):
- **Таймфреймы:** решение на **5-мин** свечах, точный вход — по **1-мин**.
- **Горизонт:** минуты–часы; по умолчанию **флэт к закрытию** сессии, перенос
  через ночь — редкое исключение.
- **Сессии MOEX:** основная (10:00–18:50) **и вечерняя** (19:00–23:50), МСК.
- **Инструменты:** весь список `MOEX_TICKERS`.

**Что это меняет в архитектуре (миграция с дневок на интрадей):**
- Технический анализ считать на интрадей-свечах через
  `MOEXPriceCollector.get_candles(interval=1|5|60)`, а не на дневках
  (`technical.fetch_candles` = `interval=24`).
- Горизонт прогноза — в минутах; оценка результата — **внутри сессии**.
- Добавить интрадей-ориентиры: **VWAP**, диапазон открытия, интрадей-ATR,
  фазы сессии, флэт к закрытию.

**Готово (тестируемое ядро):** `src/analysis/intraday.py` — чистые функции:
`vwap`, `intraday_atr`, `candle_anatomy`, `opening_range` + `orb_signal`,
`volatility_state` (сжатие→расширение), `detect_spike` + `classify_event` +
`news_whipsaw_plan` (вход на разрешении выноса), `session_phase` /
`is_last_minutes`. Покрыто тестами `tests/test_intraday.py` (11 шт.).

**Подключено к пайплайну:** `analyst.analyze` строит интрадей-контекст
(`intraday_analyst.build_intraday_context`), передаёт его в промпт Claude
(`intraday_context`), применяет интрадей-гвард (режим «наблюдение» в вынос/у
края сессии; при подтверждении — направление и план из ORB / разрешения выноса),
ставит короткий горизонт (`INTRADAY_HORIZON_HOURS`) и оценивает прогноз по
интрадей-цене (`realized_price_after`), с откатом на дневной close. Источник
данных: Tinkoff realtime при наличии `TINKOFF_TOKEN`, иначе MOEX ISS (задержка
~15 мин, помечается `delayed`). Флаги в `config/settings.py`:
`INTRADAY_MODE`, `INTRADAY_TF_MIN`, `INTRADAY_HORIZON_HOURS`,
`INTRADAY_OPENING_RANGE_BARS`.

**Осталось на будущее:** интрадей-график для Claude Vision (сейчас vision на
дневках), тонкая настройка размеров/частичных выходов, обучаемые веса сетапов.

## Стратегия 2 — Торговля волатильности (интрадей)

### Идея
Торгуем не направление само по себе, а **поведение размаха цены**. Три сетапа:
1. **Сжатие → расширение (squeeze breakout).** `volatility_state` ловит, когда
   ATR у минимумов (сжатие); входим по факту расширения (импульс из сжатия),
   а не заранее.
2. **Пробой диапазона открытия (ORB).** `opening_range` (первые ~30 мин) +
   `orb_signal`: выход за хай/лоу диапазона открытия, стоп за противоположную
   границу, цель по ATR.
3. **Разрешение новостного выноса.** `detect_spike`+`classify_event` находят
   вынос (спайк > k·ATR + аномалия сообщений/новость). Сам прострел **не
   торгуем** (режим «наблюдение»), а по `news_whipsaw_plan` входим на
   **разрешении**: пробой-и-удержание за границу пост-новостного диапазона с
   подтверждением по VWAP; стоп — за противоположную тень, цель — измеренное
   движение; тайм-стоп — к закрытию сессии.

### Статус
- ✅ Ядро логики (чистые функции + тесты) — `src/analysis/intraday.py`.
- ✅ Подключение к живому пайплайну — `src/agent/intraday_analyst.py` +
  интеграция в `analyst.analyze` (контекст в промпт, режимы «наблюдение/
  разрешение», интрадей-горизонт и интрадей-оценка). Данные: Tinkoff realtime
  или MOEX ISS (с задержкой).
- ⬜ Связка с обучением: тегировать закрытые сделки (`news_shock`, `regime_change`)
  и подмешивать уроки — механизм post-mortem уже готов (Стратегия 1).

### Ограничения
- «Волатильность как инструмент» (опционы / индекс RVI) **не поддерживается** —
  нет данных по опционам и исполнения. Торгуем волатильность **в самой акции**.
- Интрадей-свечи MOEX ISS с задержкой ~15 мин на бесплатном доступе — для
  раннего входа в быстрые движения нужен реалтайм-фид (платно). Учитываем при
  оценке «свежести» сигнала.
